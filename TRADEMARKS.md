# Use of the Wirelith name

The code and the specification are MIT licensed, and anyone may implement the specification without permission. This page covers the name only. Its purpose is to make sure people can trust what "Wirelith" means.

## Allowed without asking

- **Saying what your product does.** "Supports Wirelith", "Built with Wirelith", "Renders Wirelith diagrams" and similar factual statements are fine.
- **Claiming compatibility, for an implementation that passes the conformance suite.** "Compatible with Wirelith 0.1" (or whichever version) is allowed for an implementation that passes the public conformance suite at that version's release tag (for example `spec-v0.1`), as long as the statement names the version. A draft version can't be claimed (spec section 14).
- **Naming a plugin or extension `something-wirelith`.** For example `markdown-wirelith` or `myeditor-wirelith`.

## Reserved

- The bare name **Wirelith**, as the name of a product, package or project, other than this one.
- The **`@wirelith`** package scope on npm, and the **`wirelith`** package name on PyPI.

## Not allowed

- **Changing the language under the same name.** A fork that changes the language must use a different name. It may say it is based on Wirelith.
- **Implying endorsement.** Nothing may suggest that this project or its maintainers endorse, certify or support a product unless they have said so in writing.

If you're unsure whether a use is fine, open an issue and ask.
